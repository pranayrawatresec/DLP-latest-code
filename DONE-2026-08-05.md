## 0. Threat-model boundary (the honest bottom line — restated)
This work **raises the bar and contains the overwhelming majority of network exfil**, but does
**NOT** make exfiltration impossible. Three limits stand (see `tier2-plan.md` §0 and
`egress-channels.html` §5):
- **Screen-view (VNC/AnyDesk/RDP)** = the analog hole. We block the tool's file-transfer/clipboard
  and can kill/network-block the tool, but software cannot stop an operator reading/photographing a
  shared screen, and killing the tool does not undo a session that already showed the screen.
- **Privileged payload (admin/SYSTEM/kernel)** can unhook the user-mode agent or read raw disk beneath
  WFP filters — defence-in-depth WITH EDR / least-privilege / OS hardening, not anti-rootkit.
- **Encrypted exfil to an ALLOWED destination** is content-blind — the lever is destination
  allowlisting + fail-secure, not content inspection.
"Zero exfiltration / nothing leaks" is not claimed and must not be. The honest highest-assurance
posture is this DLP **plus** EDR + least-privilege + (top end) air-gap.

## 1. Network egress control (③) — `dlp-agent/src/netfilter/`  ✅ build/test-verified
User-mode WFP (`FwpmFilterAdd0` at `ALE_AUTH_CONNECT_V4/V6`, `FWP_ACTION_BLOCK/PERMIT`, conditions
`ALE_APP_ID` / `IP_REMOTE_ADDRESS` / `IP_REMOTE_PORT`) — no kernel callout needed for block/permit.
- `rules.rs` — pure decision engine, modes **monitor** (default, audit-only, never blocks) /
  **allowlist** (default-deny) / **blocklist** (default-permit); allow/deny by app-id, IP/CIDR, port;
  first-match. `wfp.rs` — builds `FWPM_FILTER0` specs as **dry-run `Planned`** structs (unit-tested
  without `FwpmFilterAdd`); live apply/teardown (own provider+sublayer, dynamic session) behind
  `--enforce` + admin. `net-monitor [--enforce <mode>]` subcommand; `[netfilter]` config.
- 🧪 Live WFP block/permit installation is operator-manual (admin/VM). Default `monitor` because
  `allowlist` is default-deny and can cut a machine off the network (documented DoS risk).

## 2. Remote-access-tool control (⑧) — `netfilter/remote_tools.rs`  ✅ build/test-verified
Signature set (process image names, publishers, relay domains, ports) for **AnyDesk, TeamViewer, VNC
(Real/Tight/Ultra), Chrome Remote Desktop, RDP-out (mstsc), Splashtop, LogMeIn**; matched **primarily
by process image name** (ports unreliable — tools fall back to 443). Actions per tool: `detect` /
`block-network` (WFP app-id block) / `kill` (TerminateProcess). 🧪 Live network-block + process kill
are operator-manual. Note: does not undo a screen-share already in progress (analog hole).

## 3. Fail-secure egress policy (B4)  ✅ build/test-verified
File-bearing `unreadable` (encrypted container) + destination NOT allowlisted ⇒ **block**. Ties the
minifilter/clipboard verdict to the network destination decision.

## 4. Browser upload hook (④) — `dlp-browser-ext/` + `dlp-agent/src/browser_host.rs`
Content visibility on the TLS-blind web-upload channel.
- ✅ **Native host** (`browser-host` subcommand): native-messaging (4-byte LE length + JSON), runs
  `detect::verdict_text`/`verdict` on the cached bundle, replies allow/block/warn, raises an incident
  (channel `web-upload`, metadata only). Protocol framing + verdict unit tests pass.
- ✅ **Extension** (MV3, Chrome/Edge): `manifest.json` (valid MV3), background service worker,
  content/inject scripts hooking file-input/drag-drop/paste uploads, native-host registration script,
  README. Structure-validated.
- 🧪 True upload interception/blocking needs a real Chrome/Edge with the force-installed extension +
  registered host — operator-manual. Chrome/Edge only (Firefox is a follow-on).
