1. What this layer does

It is the "badge printer" of the whole trust model. Four capabilities:

Create the root CA

One key pair + self-signed certificate, generated once on the server box. The single root of trust everything else derives from.

Issue the server certificate

The identity the agent-listener presents over mTLS, so agents can prove they're talking to the genuine server — not a counterfeit console.

Sign agent CSRs

During enrollment, turn an agent's certificate request into a signed client certificate. The identity is server-assigned, never what the request asked for.

Serve trust material

Hand the mTLS listener its key/cert and the CA as the anchor for verifying agent certificates.

2. How it connects to the admin login we already built

The CA doesn't authorize agents on its own — a human sysadmin, authenticated and authorized by the existing RBAC system, is the root of an agent's authority. The two planes meet at exactly one seam: the enrollment token (built next). CA creation itself is a setup action recorded in the same tamper-evident audit log as every admin action.

3. Architecture & certificate hierarchy

                 ┌───────────────────────────────┐
                 │   Root CA  (self-signed)       │   RSA-4096, 10 yr
                 │   CA:TRUE, pathlen:0           │   keyCertSign + cRLSign
                 │   ca-key.pem  (crown jewel)    │
                 └───────────────┬───────────────┘
                        signs    │
              ┌──────────────────┴──────────────────┐
              ▼                                      ▼
   ┌─────────────────────┐              ┌─────────────────────────┐
   │ Server certificate  │ RSA-2048     │ Agent certificates      │ RSA-2048
   │ EKU: serverAuth     │ 2 yr         │ EKU: clientAuth         │ 1 yr
   │ SAN: dns + 127.0.0.1│              │ CN: server-assigned id  │
   │ (mTLS listener)     │              │ (one per enrolled PC)   │
   └─────────────────────┘              └─────────────────────────┘
        proves the server                    proves each agent
        to agents                            to the server

Single-level CA by design: pathlen:0 forbids sub-CAs. An offline root / intermediate split and an HSM are deferred to Phase 6 hardening.

5. Security best practices applied

  • Key generation via Node's native OpenSSL-backed CSPRNG
  • node-forge only assembles/signs the X.509 structure
  • 128-bit random, positive serial numbers (unpredictable)
  • CA: basicConstraints cA:TRUE, pathlen:0 (critical)
  • CA keyUsage limited to keyCertSign + cRLSign
  • Leaf EKU split: serverAuth vs clientAuth
  • SAN-based server identity (modern TLS ignores CN)
  • Subject & Authority Key Identifiers for chain building
  • CSR identity ignored — CA assigns the name (anti-spoofing)
  • Proof-of-possession: CSR self-signature verified before signing
  • Optional AES-256 encryption of the CA key at rest
  • Refuses to overwrite an existing CA (anti-footgun)
  • Clock-skew backdating of notBefore
Why node-forge and not native cert minting? Node's crypto can generate keys and read/verify certificates but cannot mint them. We rejected @peculiar/x509 (drags in a DI framework + reflection polyfill — needless supply-chain surface for an air-gapped product) and hand-rolled ASN.1 (the "don't roll your own crypto" trap). node-forge is a single, pinned dependency that only builds structure; the sensitive key generation stays in native crypto, and every output is cross-checked by two independent verifiers.

6. Public API — lib/ca.js

caExists()                          // is the CA initialized?
initializeCa({ commonName, organization, country,
               serverDnsNames, serverIpAddresses,
               passphrase, force })  // one-time: root CA + server cert
signCertificateRequest(csrPem, { commonName, validityDays, passphrase })
                                    // enrollment core: CSR -> client cert
loadCaCertificatePem()              // the public trust anchor
loadServerTlsMaterial()             // { key, cert, ca } for the mTLS listener
canonicalSerial(serial)             // normalize serials for peer-cert matching

Pure crypto + filesystem. It never touches the database or audit log — callers own persistence and auditing, which keeps the module unit-testable in isolation. bin/init-ca.js is the thin CLI that adds the ca.init audit entry.

Adversarial cases explicitly covered

  • Agent tries to name itself (T12) — a CSR requesting CN=i-am-the-sysadmin still gets the server-assigned identity; the requested name never reaches the certificate.
  • Forged / replayed CSR (T15) — a CSR whose self-signature was tampered is rejected, so an attacker can't get a certificate for a key they don't hold.
  • Counterfeit CA (T17) — a certificate from an unrelated CA fails verification against ours, under both Node and OpenSSL.
  • Operator footgun (T03) — re-running init can't silently destroy the live CA.
