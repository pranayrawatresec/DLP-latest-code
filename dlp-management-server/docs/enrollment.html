2. The two design pillars

Two trust surfaces, never mixed

The console port trusts session cookies from humans; this agent port trusts client certificates from machines. /agent/enroll is the one route reachable without a cert (a new PC has none yet) — everything past it enforces req.socket.authorized.

Enrollment is one atomic transaction

Consume-token → insert-agent → sign-CSR → bind-serial either all commit or all roll back. A malformed CSR or weak key releases the token use — a failed enrollment never burns a seat or leaves a half-created agent.

3. Security best practices applied

  • Agent generates its own key; only the CSR (public key) is sent
  • Server-assigned identity — the CSR's requested name is ignored
  • Weak / non-RSA keys rejected (RSA < 2048 refused)
  • Atomic transactional enrollment (no wasted token uses)
  • Mutual TLS, minVersion TLSv1.2
  • Fail-secure de-enrollment: retired agent refused at check-in
  • Revocation via DB status — no CRL infra needed on-prem
  • 64 KB body cap on the unauthenticated enroll endpoint
  • Flood-resistant auditing: unknown-token probes are not logged; recognized-token misuse is
  • Routine check-ins not audited; transitions & refusals are
Why unknown-token attempts aren't audited. The append-only log can't be pruned, so logging every random-token probe would let an attacker bloat it. A valid deployment never produces "unknown token" (installers carry real tokens), so we reject those generically without a log row, while still auditing every recognized-but-unusable token (revoked / expired / exhausted) — the events that actually signal misuse.

Adversarial cases explicitly covered

  • Agent names itself (N01) — a CSR requesting i-want-to-be-admin still gets the server-assigned dlp-agent-<id>.
  • Wasted-token attack via bad CSR (N08) — a valid token + malformed CSR rolls back, so the token is still usable.
  • Counterfeit agent (N13) — a client cert from a rogue CA can't even pass the mTLS gate.
  • Self-signed / unenrolled cert (N14) — chains to our CA but no agent owns the serial → refused.
  • Double-spend race (N10) — 8 agents, one single-use token, exactly one wins.
  • De-enrolled agent (N15) — retiring an agent stops its check-ins immediately, no PC access needed.

6. API

POST /agent/enroll      { token, csrPem, hostname, os?, agentVersion? }
                        → 201 { agentId, certificate, ca, checkinIntervalSeconds }
                        (no client cert required — the one bootstrap door)

POST /agent/checkin     { agentVersion? }                        [requires client cert / mTLS]
                        → 200 { status, agentId, checkinIntervalSeconds, policyBundle:null }
